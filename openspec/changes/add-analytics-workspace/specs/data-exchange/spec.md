# Spec Delta

## Purpose

Загрузка реальных или подготовленных данных о лесосеках в систему и выгрузка результатов: таблицы и печатное заключение. Показывает, что прототип готов работать с данными заказчика.

## ADDED Requirements

### Requirement: Импорт лесосек
Пользователь SHALL загружать лесосеки из CSV (разделители «;» или «,», UTF-8) или JSON — кнопкой «Импорт» в рабочих областях или перетаскиванием файла в окно. Каждая корректная строка MUST превращаться в лесосеку с `dataSource = 'imported'` и оцениваться движком.

#### Scenario: Перетаскивание CSV
- **WHEN** пользователь перетаскивает в окно корректный CSV с 3 лесосеками
- **THEN** 3 лесосеки добавлены и оценены, камера летит к первой, в журнале событие «Импортировано 3 лесосеки»

### Requirement: Формат и шаблон
Система SHALL принимать колонки:
- `site_id`, `region_id`, `forestry`, `sub_forestry`, `quarter`, `plot`, `area_ha`, `lon`, `lat`;
- `district_id`, `site_condition`, `felling_type`, `felling_year`, `inspection_date`;
- `undergrowth_surveyed`, `occurrence`;
- `undergrowth` — записи `порода:высота:шт_га:жизнеспособность` через «;» в кавычках или через «|».

Кнопка «Скачать шаблон» MUST отдавать CSV с заголовком и двумя примерами.

#### Scenario: Шаблон
- **WHEN** пользователь скачивает шаблон и, не меняя, импортирует его обратно
- **THEN** импортируются 2 лесосеки без ошибок

### Requirement: Валидация импорта
Импорт SHALL проверять обязательные поля, допустимые коды пород, групп высоты, ТЛУ, типа рубки и района, а также диапазоны чисел. Ошибки MUST выводиться списком «строка N: поле — причина». Корректные строки импортируются, некорректные пропускаются.

#### Scenario: Ошибка в одной строке
- **WHEN** в CSV из 5 строк у третьей `site_condition = Z9`
- **THEN** импортированы 4 лесосеки, в отчёте «строка 3: site_condition — неизвестный код ТЛУ Z9»

### Requirement: Восполнение необязательных полей
Если не указан `region_id`, система SHALL определять субъект по координатам (точка в полигоне). Если не указан `district_id` — по правилу субъекта. Если нет контура — строить квадрат площадью `area_ha`. Если лесосека вне всех субъектов набора, строка MUST отклоняться с понятной причиной.

#### Scenario: Без субъекта
- **WHEN** у строки есть `lon=44.0`, `lat=57.2`, но нет `region_id`
- **THEN** лесосека получает `regionId = 'RU-NIZ'`

### Requirement: Экспорт результатов
Пользователь SHALL выгружать видимые лесосеки с решениями в CSV: идентификация, адрес, площадь, решение, достоверность, коэффициент достаточности, встречаемость, меры, состав, густота, материал, сеянцы, стоимость. Формат MUST быть UTF-8 с BOM и разделителем «;», чтобы файл открывался в Excel.

#### Scenario: Экспорт отфильтрованного
- **WHEN** включён фильтр «Искусственное» по Кировской области, и пользователь нажимает «Экспорт лесосек»
- **THEN** скачивается CSV только с этими лесосеками, русские буквы корректно отображаются в Excel

### Requirement: Печатная форма заключения
Для выбранной лесосеки SHALL быть доступна печатная форма «Заключение о необходимости проведения мероприятий по лесовосстановлению» в светлой теме, формат A4. В ней MUST быть:
- адрес и характеристики лесосеки;
- данные о подросте;
- решение и обоснование (шаги трассировки со ссылками на НПА);
- технологическая карта;
- достоверность;
- пометки «демо-нормативы, не сверено», где это так;
- поля для подписи.

#### Scenario: Печать
- **WHEN** пользователь нажимает «Печатная форма» в карточке и затем Ctrl+P
- **THEN** предпросмотр печати показывает 1–2 страницы A4 без элементов HUD и тёмного фона
