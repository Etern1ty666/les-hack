# Design

## Context

Волна 2. К её началу в коде уже есть движок (`evaluateAll`, `diffDecisions`), полный набор данных, карта и HUD. Слои экрана: `Workspace` — верхний слой (foundation D1, спецификация `app-shell` «Слои экрана»).

## Goals / Non-Goals

**Goals:** понятные красивые графики в стиле HUD, мгновенный предпросмотр нормативов, надёжный импорт и экспорт.
**Non-Goals:** сохранение конфигов и импортов на сервере: всё живёт в памяти вкладки. Экспорт в XLSX не нужен, CSV с BOM открывается в Excel.

## Decisions

### D1. Структура `src/workspace/`

```
index.tsx                  # Workspace: AnimatePresence по view ('analytics' | 'norms'), подложка-затемнение
charts/                    # собственные SVG-компоненты: StackedBarsH, GroupedBars, Histogram, StackedColumns, ChartTooltip
analytics/                 # AnalyticsView, секции, regionsTable.ts (агрегаты + сортировка + CSV)
norms/                     # NormsView, sections/*, useNormsPreview.ts, validateNorms.ts, normsIo.ts
exchange/                  # ImportDropzone (глобальный), ImportDialog, parseSites.ts, csvTemplate.ts, exportSites.ts
report/                    # SiteReport.tsx (печатная форма), openReport.ts
```

### D2. Графики: собственный SVG, без chart-библиотек

Почему: полный контроль над видом в стиле HUD и ноль конфликтов зависимостей. Нужно всего 4 типа графиков.

Правила оформления:
- фон прозрачный (график стоит внутри `Panel`);
- сетка — только горизонтальные или вертикальные линии 1 px `rgba(157,181,174,.08)`;
- подписи осей — 11 px `--text-2`, числа — JetBrains Mono, значения — через `domain/format`;
- цвета решений и пород только из `DECISIONS` и `SPECIES`, других цветов нет;
- скругление 2 px только у концов полос; без теней, градиентов и 3D;
- тултип — Panel dense: значение, доля, число лесосек;
- появление — полосы растут от нуля за 600 мс с ease-out, при reduced motion сразу;
- у каждого графика заголовок-вывод, а не название оси: «Иркутская и Красноярский — 31 % площади искусственного».

Раскладка «Аналитики» — сетка 12 колонок:
- KPI-ряд;
- решения по субъектам (8 кол.) и потребность в сеянцах (4 кол.);
- гистограмма достаточности (6) и годы рубки (6);
- бюджет (12);
- таблица (12).

### D3. Агрегаты аналитики

Одна мемоизированная функция `buildAnalytics(visibleIds, sitesById, decisions)` за один проход по лесосекам:
- по субъектам: площадь по решениям, число лесосек, площадь посадки, сеянцы, бюджет;
- по породам и материалу: сеянцы по `composition × seedlingsTotal`;
- гистограмма достаточности по площади;
- по годам рубки.

Цель — ≤ 80 мс на 60 000 лесосек.

### D4. Предпросмотр нормативов (`useNormsPreview`)

- Черновик хранится в локальном состоянии вида, стор не меняется до «Применить».
- Дебаунс 300 мс. Затем `evaluateAll(sites, draft)` → `diffDecisions(store.decisions, preview)`.
- Если оценка дольше 150 мс, она переносится в Web Worker (`new Worker(new URL('./previewWorker.ts', import.meta.url), {type:'module'})`), чтобы UI не подвисал. Начать без воркера; добавить, если Performance покажет long task.
- Матрица переходов 4×4: строки «было», столбцы «стало», ячейка = число лесосек. Диагональ приглушена, ячейки вне диагонали окрашены по цвету «стало» с прозрачностью, пропорциональной значению.

### D5. Импорт

- Парсинг — `papaparse` (`header: true`, `skipEmptyLines`, автоопределение разделителя). JSON — массив объектов с теми же ключами или массив `CuttingSite`.
- Колонка `undergrowth`: записи через `|` или `;` внутри кавычек, поля через `:`, например `spruce:medium:2000:0.9`. Высота — `small | medium | large`; жизнеспособность — доля 0–1 или процент 0–100 (> 1 → / 100).
- Субъект по координатам: point-in-polygon по `dataset.regionShapes`; район — по правилу из `src/data/regions.meta.ts`.
- id: если `site_id` пуст → `IMP-0001…`. Если id занят → суффикс `-2`.
- После `addSites`:
  - `pushFeed({type: 'import'})`;
  - `requestCamera` к первой лесосеке на зум 13;
  - если импортирована одна лесосека — `selectSite`.
- Глобальная зона drop: при `dragenter` с файлами на весь экран появляется оверлей «Отпустите файл для импорта».

### D6. Экспорт

- CSV: `'﻿' + rows.join('\r\n')`, разделитель `;`, десятичный разделитель — запятая (для русского Excel). Скачивание через `Blob` и `URL.createObjectURL`.
- Имена файлов:
  - `podrost-sites-YYYYMMDD-HHmm.csv`;
  - `regions.csv`;
  - `norms-<version>.json`.

### D7. Печатная форма

- Открывается в новом окне (`window.open`) со своим HTML и CSS: светлая тема, шрифт Exo 2, A4, `@page { size: A4; margin: 16mm }`.
- Отдельный шаблон собирается функцией `renderReportHtml(site, decision, norms)` в строку, без React, чтобы окно не зависело от бандла.
- Структура:
  1. шапка «Заключение № <id> от <дата>»;
  2. реквизиты лесосеки (таблица);
  3. подрост (таблица);
  4. решение (крупно) и достоверность;
  5. обоснование — нумерованные шаги трассировки со ссылками на НПА и пометками «демо-норматив, не сверено»;
  6. технологическая карта (таблица);
  7. прогноз успешности и факторы;
  8. подписи «Составил / Проверил» с линиями;
  9. футер «Сформировано системой ПОДРОСТ (прототип), данные демонстрационные».
- Кнопка «Печатная форма» появляется в `src/hud/Dossier/sections/Actions.tsx`, это согласованное изменение папки hud.

## Risks / Trade-offs

- [Предпросмотр 60 000 лесосек тормозит ввод] → дебаунс и Web Worker при необходимости (D4).
- [Excel неправильно открывает CSV] → BOM, `;`, десятичная запятая; проверить в Excel и в LibreOffice.
- [Импорт «грязных» данных] → построчная валидация с понятными ошибками, частичный импорт.
