# Правила для ИИ-ассистентов

Ты работаешь в репозитории хакатонного прототипа «ПОДРОСТ»: поддержка решений о лесовосстановлении (Рослесхоз, трек 4, задача 3). Разработка идёт по спецификациям OpenSpec.

## Перед началом работы

1. Прочитай `openspec/config.yaml`: там контекст проекта, стек и владение папками.
2. Прочитай `docs/task.md` и `docs/domain-glossary.md`. Для визуальных задач — также `docs/visual-direction.md`.
3. Определи свой change (`openspec list`) и работай через `/opsx:apply <change>` или `openspec instructions apply --change <change> --json`.
4. Контракты (типы, стор, сигнатуры модулей) описаны в `openspec/changes/setup-app-foundation/design.md`. После волны 0 они лежат в `src/domain`, `src/state`, `src/engine/index.ts`, `src/data/index.ts`.

## Жёсткие правила

- **Только свои папки.** Владение указано в `openspec/config.yaml`. Если для задачи нужно изменить чужую папку или контракт — остановись и скажи об этом человеку. Молча не меняй.
- **Не меняй стек** и не добавляй крупные зависимости (UI-киты, chart-библиотеки, state-менеджеры) без отдельного change.
- **Весь текст интерфейса — на русском.** Числа: пробел-разделитель тысяч, «га», «шт/га», «₽». Форматирование — только через `src/domain/format.ts`.
- **Цвета, шрифты и размеры — только из токенов** (`src/styles/tokens.css`, `src/domain/constants.ts`). Без хардкода hex в компонентах.
- **Нормативы — только из `NormsConfig`.** Никаких числовых норм в коде движка или UI.
- **Никаких ключей и секретов.** Только публичные бесключевые источники.
- **Синтетика маркируется.** Бейдж «Демо-данные» не убирать.
- **Производительность:** никаких `setState` и записей в стор на каждом кадре анимации. Анимации карты — через пропсы deck.gl в rAF.
- **Клавиши** — строго по таблице распределения (foundation design D13).

## Команды

```bash
npm run dev          # дев-сервер
npm run typecheck    # проверка типов
npm test             # vitest
npm run build        # прод-сборка
npm run data:build   # пересборка данных (поток dataset)
openspec validate --all --strict
```

## Определение «готово» для задачи

- Выполнено описанное в задаче и проверено способом, который в ней указан.
- `npm run typecheck && npm test` проходят.
- Чекбокс в `tasks.md` отмечен только после полной реализации, частичную не отмечай.
- Для визуальных задач в PR приложен скриншот или GIF.

## Если что-то не так

- Спека противоречит дизайну или контракту → остановись и предложи правку артефакта (`/opsx:update`). Не «додумывай».
- Задача требует больше, чем описано → опиши дополнительный объём и спроси.
- Внешний тайл-сервер недоступен → это не баг кода. Проверь деградацию по спецификации карты.
