# Spec Delta

## Purpose

Оболочка приложения «ПОДРОСТ»: управляет жизненным циклом (загрузка данных, оценка лесосек, интро, рабочий режим), задаёт слои экрана и общий визуальный язык, честно маркирует демо-данные.

## ADDED Requirements

### Requirement: Фазы жизненного цикла
Приложение SHALL проходить фазы `boot → loading → intro → ready` строго по порядку. В фазе `loading` оно MUST загрузить набор данных и оценить все лесосеки. Переход в `ready` MUST происходить только по действию пользователя на интро-экране.

#### Scenario: Успешный запуск
- **WHEN** пользователь открывает приложение и данные загружаются без ошибок
- **THEN** сначала показывается экран загрузки с прогрессом, затем интро-карточка с кнопкой «Начать»
- **AND** после нажатия «Начать» или клавиши Enter фаза становится `ready`

#### Scenario: Пропуск интро клавишей
- **WHEN** фаза `intro` и пользователь нажимает Enter или Space
- **THEN** фаза становится `ready` так же, как при нажатии кнопки

### Requirement: Экран загрузки с прогрессом
Во время фазы `loading` приложение SHALL показывать полноэкранный экран загрузки: логотип, название текущего шага и числовой прогресс. После оценки MUST показываться итог «Проанализировано N лесосек».

#### Scenario: Отображение шагов
- **WHEN** идёт загрузка набора данных и затем оценка лесосек
- **THEN** экран последовательно показывает шаги «Загрузка данных» и «Анализ лесосек» с прогрессом
- **AND** после завершения показывает «Проанализировано 60 000 лесосек» (число берётся из данных)

### Requirement: Ошибка загрузки
Если загрузка данных или оценка завершилась ошибкой, приложение SHALL перейти в фазу `error` и показать понятное сообщение на русском с кнопкой «Повторить».

#### Scenario: Недоступен файл данных
- **WHEN** загрузка набора данных выбрасывает исключение
- **THEN** показывается экран ошибки с текстом причины и кнопкой «Повторить»
- **AND** «Повторить» заново запускает фазу `loading`

### Requirement: Слои экрана
Приложение SHALL рисовать три слоя снизу вверх: карта на весь экран, HUD поверх карты, рабочие пространства («Аналитика», «Нормативы») поверх HUD. Нижние слои при этом MUST оставаться смонтированными. Размеры зон HUD MUST задаваться CSS-переменными из дизайн-токенов.

#### Scenario: Переключение вида не перезагружает карту
- **WHEN** пользователь переключается с «Карты» на «Аналитику» и обратно
- **THEN** карта не размонтируется, положение камеры сохраняется

### Requirement: Бейдж демо-данных
Пока в наборе есть синтетические лесосеки, на экране SHALL постоянно виден бейдж «Демо-данные · синтетика», а в подсказке к нему MUST объясняться происхождение данных.

#### Scenario: Бейдж виден в любом виде
- **WHEN** фаза `ready`, и открыт любой вид (карта, аналитика, нормативы)
- **THEN** бейдж «Демо-данные» виден и не перекрывает основные элементы управления

### Requirement: Единый визуальный язык
Все цвета, шрифты, отступы и размеры зон SHALL браться из дизайн-токенов (`src/styles/tokens.css`). Цвета решений MUST быть одинаковыми во всех компонентах.

#### Scenario: Цвет решения совпадает в бейдже и на карте
- **WHEN** лесосека имеет решение «Искусственное»
- **THEN** бейдж в HUD и точка на карте используют один и тот же цвет `--artificial` / `DECISIONS.artificial.rgb`

### Requirement: Уважение к prefers-reduced-motion
При системной настройке `prefers-reduced-motion: reduce` приложение SHALL сокращать или отключать декоративные анимации: интро-облёт, пульсации, count-up чисел.

#### Scenario: Пользователь с ограничением анимаций
- **WHEN** в системе включено уменьшение движения
- **THEN** числа появляются сразу без count-up, а переходы панелей длятся не дольше 100 мс
