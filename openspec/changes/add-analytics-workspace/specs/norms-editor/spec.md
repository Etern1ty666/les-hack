# Spec Delta

## Purpose

Редактор нормативов модели: пользователь меняет пороги и нормы, видит, сколько решений по стране изменится, и применяет изменения с мгновенным пересчётом карты. Показывает, что модель опирается на нормы и легко адаптируется к НПА.

## ADDED Requirements

### Requirement: Вид «Нормативы»
При `view = 'norms'` SHALL открываться рабочая область с разделами:
- глобальные параметры: коэффициенты высоты, `minOccurrence`, `combinedLowerRatio`, `maxUndesiredShare`;
- нормативы по лесным районам: таблица район × три группы пород;
- густота посадки;
- тарифы.

#### Scenario: Открытие нормативов
- **WHEN** пользователь нажимает вкладку «Нормативы»
- **THEN** видны 4 раздела, значения взяты из текущих `norms` стора

### Requirement: Источник каждого значения
Рядом с каждым параметром и строкой района SHALL отображаться источник (`NormativeRef.doc`) и метка «не сверено», если `verified = false`. Пользователь MUST иметь возможность отметить значение как сверенное.

#### Scenario: Отметка сверки
- **WHEN** пользователь отмечает строку `south_taiga_eu` как сверенную
- **THEN** метка «не сверено» исчезает, и после «Применить» в карточках лесосек этого района ссылка показывается без метки

### Requirement: Живой предпросмотр
При изменении любого значения редактор SHALL с задержкой 300 мс пересчитывать все лесосеки на черновике нормативов, не меняя карту. Он MUST показывать число изменившихся решений и матрицу переходов 4×4.

#### Scenario: Ужесточение встречаемости
- **WHEN** пользователь меняет `minOccurrence` с 65 % на 75 %
- **THEN** не позже чем через 1 с видно «Изменится решений: N» и ненулевая ячейка «Естественное → Комбинированное»

### Requirement: Применение
Кнопка «Применить» SHALL записывать черновик в стор (`setNorms`), что пересчитывает решения и перекрашивает карту. Затем MUST добавляться событие журнала `norms_changed` с числом изменений.

#### Scenario: Применить изменения
- **WHEN** пользователь нажимает «Применить»
- **THEN** решения в сторе обновлены, карта перекрашена с плавным переходом, в журнале — «Нормативы обновлены: изменилось N решений»

### Requirement: Валидация значений
Редактор SHALL не давать применить некорректные значения:
- доли вне 0–1;
- отрицательные нормативы или тарифы;
- `combinedLowerRatio ≥ 1`;
- коэффициенты высоты вне 0–1.

Ошибка MUST показываться у поля.

#### Scenario: Некорректный порог
- **WHEN** пользователь вводит `combinedLowerRatio = 1,2`
- **THEN** поле подсвечено ошибкой «Должно быть меньше 1», кнопка «Применить» неактивна

### Requirement: Сброс, экспорт и импорт
Редактор SHALL уметь:
- сбрасывать черновик к `DEFAULT_NORMS`;
- экспортировать текущий конфиг в JSON;
- импортировать конфиг из JSON с проверкой структуры.

#### Scenario: Импорт битого файла
- **WHEN** пользователь загружает JSON без поля `districts`
- **THEN** показывается ошибка «Файл не похож на конфиг нормативов: нет поля districts», черновик не меняется
